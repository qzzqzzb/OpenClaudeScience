# 第四阶段改动过程

## 起点判断

第三阶段已经完成：

- 前端 Agent Runtime Adapter 边界收口。
- `useChat.ts` 的 run 控制入口收口到 `useAgentRuntimeStream()`。
- coordinator / runtime / RemoteGraph / DeepAgents / Skills / MCP / subagents 关系图已补齐。

第四阶段进入：

```text
Runtime Protocol 标准化
  -> MockRuntimeProvider 验证
    -> OpenCodeRuntimeAdapter 评估
```

## 4.3 新增 LangGraph stream 到中立事件的旁路 mapper

目标：

- 明确当前 LangGraph SDK stream event 如何映射到 `AgentRuntimeRunEvent`。
- 先做旁路转换函数和测试，不接入 `useChat.ts` 主链路。
- 只覆盖能稳定判断的消息、工具调用、工具结果、中断、状态、错误事件。

改动范围：

```text
ui/src/lib/langgraph-runtime-event-mapper.ts
ui/tests/langgraph-runtime-event-mapper.test.mts
ui/package.json
docs/architecture/第四阶段改动过程.md
docs/architecture/第四阶段RuntimeProtocol设计.md
docs/architecture/后续改造.md
```

新增能力：

```text
mapLangGraphStreamEventToRuntimeEvents()
mapLangGraphStreamEventsToRuntimeEvents()
```

当前映射：

```text
messages/messages-tuple assistant chunk -> message_delta
assistant tool_calls -> tool_call
tool message -> tool_result
__interrupt__ -> interrupt
values/updates -> state（仅 includeStateEvents=true）
error -> error
```

谨慎点：

- 不猜测 LangGraph run_started / done，因为当前 tapped SDK event 没有稳定携带 run 生命周期。
- 不生成 message_completed，因为 messages-tuple chunk 本身不能可靠判断 assistant 消息是否完成。
- 不修改 `WebRemoteAgent`。
- 不修改 `useChat.ts`。

验证：
