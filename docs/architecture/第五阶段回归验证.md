## 本轮补充修复

全量本地测试时发现 `chat-errors.test.mts` 失败：

```text
TypeError: t is not a function
```

原因：

- `formatChatError(error, t)` 在 UI 中由组件传入真实翻译函数。
- 单元测试直接调用 `formatChatError(message)`。
- 原实现没有默认翻译函数。

修复：

```text
ui/src/lib/chat-errors.ts
```

修复内容：

- 给 `formatChatError()` 增加默认中文翻译函数。
- 给 `extractRemoteRuntimeErrorMessage()` 增加默认中文翻译函数。
- 使用 `translate("zh", key, params)`，不复制文案。

影响：

- UI 传入真实 `t` 时行为不变。
- 测试和兜底调用不再报错。

## Build 验证

命令：

```text
npm run build
```

结果：

```text
failed
```

失败信息：

```text
EPERM: operation not permitted, scandir 'C:\Users\LeoHao\Application Data'
```

判断：

- 失败发生在 Next standalone / webpack tracing 扫描 Windows 用户目录时。
- 不是 TypeScript 编译错误。
- 不是 lint 错误。
- 不是本轮 runtime protocol 或 adapter 分层代码错误。
- 当前尝试过 output tracing exclude，但该错误发生在更早的 glob 推断阶段，未生效，因此没有提交规避性配置。

建议：

```text
后续如果需要生产构建稳定通过，应单独处理 Windows standalone tracing 与 os.homedir()/用户目录动态访问的问题。
这可以作为独立构建工程任务，不混入本轮架构边界改造。
```
